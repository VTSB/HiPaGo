# Default Result Filter

## Context

Users can already search with positive and negative terms such as `female:big_breasts -artist:yam`. The app also has blur tags, but blur tags only obscure thumbnails and do not remove galleries from result sets.

## Decision

Add a persisted default result filter query in settings. The value uses the existing search syntax and is applied to every main-list and search result set.

Examples:

- `-male:yaoi` excludes that tag from the main list and from all searches.
- `female:big_breasts` restricts the main list and searches to that tag.
- `female:big_breasts -artist:yam` applies both inclusion and exclusion.

The settings input uses tag suggestions for the active whitespace token. If the active token starts with `-`, suggestions search the token body and keep the negative marker when a tag is selected.

## Execution Model

For search pages, combine the user query and default filter query with a single space before executing search. The visible search text and URL remain the user query; the default filter is stored in settings.

For the main gallery list, a non-empty default filter switches the list from paged browse fetching to an ID-list search result generated by `getGalleryIdsForQuery(defaultFilterQuery, language, sort)`. This lets positive and negative default filters use the same semantics as normal search. With no default filter, the existing paged browse path stays unchanged.

## Tradeoff

A default filter on the main list needs a full filtered ID list in memory. This is intentional so the virtual grid can apply arbitrary positive/negative search semantics consistently across list and search surfaces.

## Verification Cue

Tests should cover settings persistence, active-token replacement with and without `-`, main-list filtered mode, and search query composition with a default negative filter.
